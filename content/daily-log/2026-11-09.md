## 今天的工作

继续推进 personal-superagent，围绕一个具体问题做原型：Agent 执行耗时工具时，怎样让用户继续和它对话，并在任务完成后收到回复？

今天把 Agent 循环、模型配置和终端交互拆开，接到统一入口上。现在可以在同一套终端界面里选择普通 ReAct Agent 或 DuplexAgent，默认使用后者。

### 后台工具执行与持续对话

把原有的 ReAct 循环整理成 `Agent` 类，并新增 `DuplexAgent`。普通 Agent 等待工具结果，再继续推理；DuplexAgent 启动工具后，先把 `started` 回执交给模型，工具在后台继续执行。用户的新消息进入输入队列，工具完成或失败也以事件形式进入队列，触发后续回复。

为这个流程加入了一个延迟 60 秒的模拟工具。它提供了一个具体的交互场景：启动任务后继续聊天，等任务完成，再让 Agent 根据结果回复。工具完成事件保留原始调用 ID，方便关联此前启动的任务。

### 支持持续输入的终端界面

新增 TUI，上方显示对话和工具日志，底部固定保留输入区。发送消息后可以继续输入，后台回复到来时保留尚未发送的草稿和光标位置。界面也加入了长文本换行、历史输入、消息翻页和窗口缩放适配。

两种 Agent 共用这套界面。普通 Agent 按顺序处理已发送的消息；DuplexAgent 把消息交给内部队列，由后台执行和完成事件推进对话。这样可以在相同的交互条件下观察两种调度方式。
