## Today's work

Continued working on personal-superagent, prototyping around a specific question: how can a user keep talking to an agent while it runs a time-consuming tool, and receive a reply when the task finishes?

Today I separated the agent loop, model configuration, and terminal interaction, and connected them through a shared entry point. The same terminal interface now supports either a standard ReAct Agent or DuplexAgent, with DuplexAgent as the default.

### Background tool execution and ongoing conversation

Refactored the existing ReAct loop into an `Agent` class and added `DuplexAgent`. The standard Agent waits for a tool's result before continuing to reason. DuplexAgent starts the tool and immediately provides a `started` acknowledgment to the model while the tool continues running in the background. New user messages enter an input queue; tool completion and failure events enter the same queue and trigger subsequent replies.

Added a mock tool with a 60-second delay to exercise this flow. It provides a concrete interaction scenario: start a task, keep chatting, and have the agent reply with the result when the task finishes. Completion events retain the original call ID so they can be associated with the task that was started earlier.

### A terminal interface that supports continuous input

Added a TUI with conversation messages and tool logs above a fixed input area. Users can keep typing after sending a message, and incoming background replies preserve the unsent draft and cursor position. The interface also supports wrapping long input, recalling input history, paging through messages, and adapting to window resizing.

Both agents share this interface. The standard Agent processes submitted messages in order. DuplexAgent passes messages to its internal queue, with background execution and completion events driving the conversation forward. This makes it possible to observe both scheduling approaches under the same interaction conditions.
