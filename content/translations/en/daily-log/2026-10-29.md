### Stanford CS197: How to Write an Introduction

The structure of an Introduction:

- **Problem**: What problem are you trying to solve?
- **Set up the bit**: Why has this problem not been solved yet?
- **Flip the bit**: Present your insight and introduce your big idea.
- **Instantiate that bit flip in a solution**: Introduce how you implement the idea.
- **Evaluate the solution**: Demonstrate how your bit flip helps solve the problem, and present experimental results.
- **Implications**: What impact does your bit flip have on the field?

Start by writing one topic sentence for each of these six points. Then expand the topic sentences into paragraphs, each making a small thesis.

- StreamVibe: [https://arxiv.org/abs/2610.34662](https://arxiv.org/abs/2610.34662)
  - Overview: a VLM, harness, and benchmark for recognizing users' explicit and implicit intent from streaming video and providing proactive assistance.
  - Problem: How can we build a proactive personal agent assistant?
  - Previous work: (1) Considers only explicit queries from users. (2) Considers only independent, single-turn requests.
  - Insight: (1) Infer users' implicit intent through continuous interaction and observation. (2) Track task-relevant state. (3) Account for dynamic changes in user intent.
  - Technical overview: (1) Constructed StreamVibe-Bench, covering explicit, implicit, and dynamic user intent in both physical and digital environments. (2) Trained StreamVibe-VL with SFT and RL as a streaming proactive model that can infer implicit user intent and adjust interactions as that intent evolves. (3) Built StreamVibe-Harness to maintain user intent as persistent, updatable state with a flexible lifecycle, while using hierarchical memory to retrieve relevant history so that subsequent decisions align with the current interaction context and user intent.
  - Proof: (1) StreamVibe-VL achieves stronger proactive interaction while preserving general video understanding. (2) Current proactive agents struggle to sustain reliable behavior over continuous interaction. (3) Policy learning improves proactive decision-making, while state tracking enhances sustained interaction stability.

### Li Li (栗力)

- SmartFed: [https://openreview.net/pdf?id=HdsEUNo4C4](https://openreview.net/pdf?id=HdsEUNo4C4)
  - Overview: an efficient federated fine-tuning method.
  - Problem: How can federated fine-tuning be made more efficient and suitable for edge devices?
  - Previous work: existing methods typically train LoRA modules from scratch.
  - Insight: reuse open-source LoRA modules.
  - Technical overview: (1) Train a router to select open-source LoRA modules. (2) Treat the different rank dimensions of each LoRA module as experts, activating only the most relevant experts for each request. (3) Allocate the budget for activating experts according to their contributions.
  - Proof: 13.82% average performance gains, 3.95× faster convergence, 31.47× lower communication overhead, and 3.61× reduced energy consumption. On math-word problems, it outperforms baselines by 8.02% while using only 10% of the training data.
- SAPrune: [https://arxiv.org/pdf/2610.05273](https://arxiv.org/pdf/2610.05273)
  - Overview:
  - Problem: How can visual token pruning accelerate VLA model inference?
  - Previous work: estimate which tokens can be pruned based on attention scores or feature diversity.
  - Insight: the model does not know which visual regions in earlier layers are important for actions.
  - Technical overview: (1) Uses a small calibration set to observe how action-to-visual attention changes across layers, and chooses pruning layers only after the attention pattern becomes more reliable. (2) At each selected layer, applies a dual-path pruning rule: one path protects strongly attended visual tokens from pruning, while the other prevents useful surrounding context from being discarded.
  - Proof: SAPrune prunes 87.5% of visual tokens and achieves up to 1.718× inference speedup while maintaining competitive task success rates.
